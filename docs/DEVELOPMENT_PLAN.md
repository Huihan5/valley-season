本文件收纳功能计划、缺陷、待讨论事项与工作记录。规则、数值、世界和角色的完整说明见 [GDD_NEXT.md](GDD_NEXT.md)。原 [GDD.md](GDD.md) 保留。

## 1. 下一轮工作

以下为已确定方向、尚未完成的工作。本轮只整理文档。

### 1.1 语言切换与存档中的显示文本

**问题**：从英文 Day 3 切换到中文，返回游戏后仍显示原来的英文场景，直到推进时段才更新；左下角记录也有同类问题。

**原因线索**：场景、事件、行动结果和记录以已经解析的字符串保存在游戏状态中；语言资源在模块加载时选择。刷新语言不等于重新生成当前状态中的文字。存档还保存语言信息，载入流程会恢复该语言。

**目标**：语言切换后，日期、资源、关系、事件进度与随机结果保持原样，当前场景、事件选项、行动结果和记录立即使用所选语言。

**实施要点**：保存内容标识、变体标识与插值参数，在显示时按语言解析。不得通过重抽场景或重新执行事件效果来“刷新”语言。兼容旧存档中的字符串记录需要单独处理。

**验收场景**：日常场景、多人固定事件、夜间待继续的行动结果、集市多笔交易、历史记录与存档载入；中英双向切换。已发生的随机结果不变化，不重复扣费、加信任或推进时间。

### 1.2 返回主界面

游戏内没有清晰的常规返回标题页入口。增加入口，先保存本季进度再退出，主界面可继续这一季。返回主界面与重新开始应当分开，避免把导航误做成重置。

具体按钮位置与存档菜单整合方式在界面实施时确定，不借此改动右栏结构。

### 1.3 所有 NPC 发言处的头像

范围覆盖**所有 NPC 发言的呈现路径**：日常招呼、行动结果、固定事件、随机事件、调查片段、连续事件、多人交谈与结局中的直接发言。

不能只补“搭把手”和“上午办公室”。Day 27 集市的 Timothy 与 Thierry 是必须覆盖的多人场景；对话在两人之间切换时，应能识别当前发言者。

实施顺序：

1. 逐项清点中英文内容中实际发言的人物，以及招呼、事件、结果、线索、结局的渲染路径。
2. 使用明确的说话者标识；旁白与人物台词分开。一个事件可以包含多个发言者，不能用整段事件的单一头像代替。
3. 让行动结果与普通招呼共用人物呈现方式。现有流程只有部分招呼路径设置人物标识，行动结果文本常绕过该路径。
4. 复用已有角色肖像。缺少肖像的人物列为美术缺口；显示人物姓名，避免错用另一人的头像。
5. 核对两种语言、连续事件的说话者切换，以及存读档后的对应关系。

现有肖像包括格雷格、玛莎、埃莱娜、洛伦茨、提莫西、蒂埃里。发言者集合大于六名有信任值的 NPC，人物标识不能直接受关系系统的六人名单限制。

本项属于呈现完善，不附带扩写对白。原有叙事内容仅在明确标识发言者或分段确有需要时调整结构。

### 1.4 点击人物，打开他的见闻条目

点击人物入口后打开 Compendium，并直接定位到该人物的条目，展示已经解锁的层次。保留解锁门槛，不因点击而提前开放“底细”或“原型”。关闭后回到原游戏位置。

关系栏人物入口是明确的使用场景；头像、姓名等其他入口可在实现时统一交互。没有现成见闻条目的人物，不能映射到不相关条目。提莫西与蒂埃里已有肖像，但尚不在见闻的六个人物条目中；补充条目属于另一个内容范围。

这一导航功能独立于右栏布局调整，可以单独推进。

### 1.5 中栏底部短句

在日常时段、中栏有余白时，放置一至两行轻量的环境观察或庄园闲笔。短句提供陪伴感，不承担必须读取的线索、规则或行动提示。

每个时段选定后保持稳定。打开菜单、见闻、切换语言或调整窗口不重抽；不使用定时轮播。长事件与结局优先使用完整阅读空间，短句不压住正文和选项。

先复用现有闲笔中的环境句，建立独立的短句池与适用条件，避免直接随机截取完整故事。首批选材方向：

| 现有句子 | 使用语境 | 处理 |
|---|---|---|
| “厨房窗玻璃上的水汽在冬天来之前就已经开始积了。” | 厨房的日常时段 | 可独立成立，作为第一批候选 |
| “风从坡上下来的时候，整片林子的声音是从高处往低处走的。” | 林地、安静的日常时段 | 可独立成立，作为第一批候选 |
| “枫叶下得像下雪。” | 庭院、落叶时节 | 使用季节条件，不与实际降雪混淆 |

来源为 src/data/zh/scenes/ambient.json；英文需选取对应内容并核对节奏。

首批不采用：已收麦茬上的鸟（需要确认收割经历）、八匹马全部熟睡（需要夜间及马匹在场条件）、晒冬被（与 Day 30 关系回应竞争）、“这一天已经没有别的事要做了”（可能与剩余行动矛盾）、退出炉堂（可能与当前地点矛盾）。

方言和谚语只使用已有设定中确立的内容。先做环境观察，不为填空白新增地方语言体系。

### 1.6 文本修订

以“这句话在什么时候成立”为第一轮检查问题：日期、时段、天气、地点、人物在场、关系、首次／重复、前置行动、已知信息及实际资源结算。

在开发记录中列出不成立的组合与修正方式，规则性原则保留在 GDD 第 11.5 节。固定事件、随机事件和普通闲笔都要检查，不能只审正文润色。

已经发现值得优先检查的例子：随机事件“第三幕的一天”包含特定天气及已完成晚间工作的描述，但抽取条件主要是日期；日常闲笔也有光照、霜化、马匹数量等额外条件。

## 2. 暂停与保留的取舍

### 2.1 右栏布局：暂停

人物关系被挤到右下角、首屏无法完整显示的问题仍然存在。作者喜欢关系区上方已有的视觉效果，但不满意之前提出的布局方案。

**不实施此前的右栏方案，不调整模块次序或大小。**“Schedule 可折叠、关系优先完整显示”保留为原始 playtest 诉求，不能当作已经批准的具体设计。重新讨论时以可比较的界面示例为基础。

### 2.2 重复文字与差异提示

重复本身是游戏的节奏与气氛，取消“重复内容自动简读”方向。重点是帮助玩家注意变化，而非减少重复阅读量。

差异提示的视觉形式尚未确定，不默认加入闪动、弹窗、数字浮条或整段高亮。

### 2.3 itch 页面与截图

截图更新等待更多 UI 调整与背景图进入游戏后再做。届时用不同体验的画面表达劳动、人物关系、调查与季节，不急于替换成多个相似日常页面。

本轮不修改 itch 页面，不发布新构建。

## 3. 后续功能与美术

### 3.1 收集物与物品列表

可行方向：让既有经历留下可以在背包或物品列表中查看的东西。例如第三次照料马匹时的第二把刷子，来自已经存在的段落。

先梳理哪些现成物件足以承载记忆，再决定界面与收集条件。不开启一轮为了反馈行动而扩写所有 NPC 对话的工程。

修过屋顶改变离别对白不作为新功能推进。代码已经存在结局一的修缮分支；本次只在 GDD 如实记录，没有新增，也没有擅自删除。若后续需要移除，作为独立文本变更处理。

林地已经随累计采伐分档变化，属于既有机制。修缮后在雨天看到具体场景变化，保留为更远期扩展。

### 3.2 结局后的“可能错过什么”

结局或结束后增加独立区块，提示本季可能错过的内容，以及下次可以在哪里寻找。与结局正文分开，保持结局的收束感。

需要继续确定：提示的剧透深度、展示范围、是否需要主动展开。可以先给人物／地点／时段方向，再由玩家决定是否查看具体条件；这属于方案候选，尚未选定最终样式。

### 3.3 场景图

考虑河谷城、庄园、狩猎季三类场景。用途可能为档案插图，或 gameplay 主界面装饰。位置、尺寸、出现频率与正文对比度尚需设计。

背景图应以可读性为基础，先用实际主界面验证文字与选择区，再定最终美术规格。截图展示更新在这一轮之后进行。

### 3.4 远期备选

- 一键推进整日：保留 idea，不进入近期实施。
- 修缮后的雨天场景反馈：远期叙事扩展。
- 将时段推进流程从根组件独立：未来技术整理。
- 支持固定随机种子的整季回放：未来验证能力。
- 技术测试体系的扩充：后续再讨论，不作为此次文档整理的前置工作。

## 4. 核对中发现的差异与缺陷

这些问题单独跟踪，不把已知的坏表现写成应当遵守的游戏规则。

| 项目 | 证据与影响 | 后续处理 |
|---|---|---|
| 雨天收割提示 | EventSystem 的收割按钮未因雨禁用，实际产量按 −2 结算；WeatherSystem.canHarvest 却使小字显示雨天不能收割 | 统一按钮说明与执行规则 |
| 磨岭木材协议 | MarketSystem 支持协议后木材单价 4；millridgeDealSigned 仅有初始值与读取点，未找到游戏行动写入；晚宴只记为考虑提议 | 恢复协议路径或清理残留，需要单独决定；GDD 常规集市价格记为 3 |
| 运营费总量 | 原预算按 30×2＝60；游戏 Day 1 不扣费，进入 Day 2–30 共扣 58 | GDD 已按实际日序说明；不为凑旧预算改变开局 |
| 经纪人日期 | 注释曾写 Day 24–30，条件在 Day 23 来信后当天下午已满足 | GDD 记为 Day 23–30；后续清理旧注释 |
| 炉堂守夜的恢复措辞 | 周四守夜只有交流与关系效果；普通炉堂独处才清疲劳 | 逐项对照 UI 说明，避免把两种行动混写 |
| 维特的位置补充段落 | Day 22 来访的第四层要求位置线四条齐全，第四条却只能在 Day 27 获得，因此正常流程不能触发 | 核对该段的用途；GDD 只列可到达的三层整理，不把死分支当作正常剧情 |
| 世界专名 | 原 GDD 中 Ludwig von Alder，与部分游戏英文中的 von Alde 不一致 | 文案统一时逐处核对正式拼写，不在本次悄悄改全局 |
| 数值集中管理 | ResourceSystem 的收割基础档位等仍有内联数值，与 config 的集中定义并存 | 未来系统整理时收敛；本轮不调整代码 |

旧 GDD 中没有对应常规入口的泛化拜访、未经落地的关系福利表、随机事件扩容目标，均未作为实际机制收入新 GDD。若重新启用，应先成为具体功能方案。
